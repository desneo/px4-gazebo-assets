# ASD-2-075-DD0 仿真协议与接口

本文件描述当前仿真组件的实际接口。产品参考文档为同目录下的《导引头标准通信协议-20260717》V3.0；仿真保留其 45/104 字节帧格式，传输层改为 UDP。

## 传输

| 项目 | 默认值 |
|---|---|
| 控制帧目的端口 | `8790`（网关监听） |
| 遥测帧目的端口 | `8791`（上位机监听） |
| 广角 RTP | `7001` |
| 长焦 RTP | `7002` |
| 控制帧 | 45 字节，一帧一个 UDP 数据报 |
| 遥测帧 | 104 字节，一帧一个 UDP 数据报 |
| 遥测周期 | 100 Hz |
| 字节序 | 小端 |
| 校验 | 字节 4 起求和取低 8 位；控制帧 4～44，遥测帧 4～103 |

UDP 不保证到达、顺序或唯一性。网关丢弃帧头、长度或校验和错误的帧；标准协议没有 ACK，上位机按遥测状态判断命令效果。上位机以 `0x00` 无效指令 10 Hz 发送心跳；网关超过 2 s 没有有效控制帧时停止跟踪和自动锁定并保持当前角度。离散命令在 200 ms 内重复帧只执行一次，`0xB1` 连续速度流不去重。遥测目标 100 Hz；演示默认 1920×1080 单路当前镜头，当前环境可保持 30 fps 和 100 Hz；同时订阅/编码两路 1080p 会因 Gazebo 渲染和 Python 图像订阅下降，网关不补发旧样本。

## 已实现命令

| 命令 | 字节 | 参数 | 行为 |
|---|---|---|---|
| 无效/心跳 | `0x00` | — | 不改变状态，仅刷新控制超时 |
| 框架电锁 | `0xE9` | — | 停止跟踪/运动，进入电锁 |
| 电锁解除 | `0x9E` | — | 解除电锁，进入自由状态 |
| 指定框架角度 | `0x90` | p1 yaw×100，p2 pitch×100 | 网关速度环转到目标角，限幅 yaw ±60°、pitch −80°～+30° |
| 指定角度电锁 | `0x14` | 同 `0x90` | 到位后进入电锁 |
| 框架归中 | `0x91` | — | 两轴回机械 0/0（载机前视） |
| 点选目标锁定 | `0xB7` | p1 x，p2 y（像素） | 选点击位置附近最近真值候选并跟踪 |
| 自动锁定 | `0x5F` | — | 选画面中心最近真值候选并跟踪；丢失后重选 |
| 关闭自动锁定 | `0xF5` | — | 停止跟踪并关闭自动锁定 |
| 取消锁定 | `0x8E` | — | 停止跟踪并保持当前角度 |
| 框架移动 | `0xB1` | p1 左右，p2 上下（−100～+100） | 映射到 ±60°/s，0.5 s 无新帧自动停车 |
| 变焦 +/- | `0xB9`/`0x9B` | — | 更新广角变倍状态位；上位机按 1×/2×/4× 中心裁剪显示 |
| 激活镜头 | `0x53` | p1=1 广角，2 长焦 | 插件切换活动 sensor、图像和真值候选；切换时停止跟踪 |

`0x5F/0xF5` 在标准协议中的原义是“自主识别后自动锁定开/关”。仿真不实现自主识别，将其解释为“真值最近中心自动锁定开/关”；该语义差异不得当作真实识别能力。

## 目标选择与跟踪

- Gazebo 插件在内部 JSON 遥测中发布 `truth_candidates`，每项包含 `name`、`center_px`、`depth` 和 `frame_seq`，来自当前广角相机和已配置的 `sim_truth_target_name`。
- 点选锁定：网关优先选择点击位置 80 px 内最近候选；附近没有目标时选择画面内最近候选，向插件发送 `track` 框。
- 自动锁定：网关在当前活动镜头的可见候选里选离画面中心最近者，向插件发送 `track` 框；插件绑定实体后只投影该实体，不因其他飞机经过换锁。
- 跟踪框由插件按初始框和深度缩放，四边各扩展 5 px 并裁剪到画面边界。
- 目标丢失超过 2.5 s 进入 LOST；自动锁定模式重新选择当前最近中心候选，手动锁定不自动换锁。
- 切换广角/长焦时插件清空旧相机的图像、真值历史和处理帧，重新以新相机内参/光轴建立跟踪；长焦可原生独立跟踪。

## PX4 19 字段 JSON

网关默认不发送 PX4 JSON；指定 `--px4-json-port` 后，以 50 Hz 将内部遥测转换为 `dyt_udp_bridge` 的 19 字段格式。字段为 `timestamp`、`track_status`、`pitch_angle`、`yaw_angle`、`pitch_misalignment`、`yaw_misalignment`、`tracking_confidence`、`target_confidence`、`gyro_pitch_rate`、`gyro_yaw_rate`、`pitch_los_rate`、`yaw_los_rate`、`los_omega_n/e/d`、`tracking_gate_w/h`、`gate_x/y`。

- `timestamp` 在 UDP 发送前生成，为 Unix 毫秒；PX4 uORB 自身时间戳仍为本机 hrt。
- `gyro_*`、`pitch_los_rate`、`yaw_los_rate` 按 ±20°/s 限幅；`los_omega_n/e/d` 取独立 `omega_ned_dps`，不按 ±20 限幅。
- 目标无效时 `track_status=0`，脱靶量、波门和中心置 0；机械角和 gyro 仍发送。
- `gate_x/y` 取最终跟踪框中心的 half-up 整数像素；`tracking_gate_w/h` 保留浮点宽度/高度。
- `--json-telemetry-port` 可把同一 19 字段 JSON 另发一份给上位机（默认演示 8792），供“发送艾晟报文”手动转发到用户指定 IP/端口。

## 视频

- 控制器只订阅当前镜头图像，非活动镜头不接收、不反序列化；两个相机传感器仍按模型配置渲染。
- 发送端：Gazebo RGB 图像 → `videoconvert n-threads=4` → `nvcudah264enc` 低延迟 CBR → 内部 RTP（`127.0.0.1:7001`）。
- RTSP 服务：内部 RTP → `rtph264depay` → `rtph264pay` → 固定挂载 `/aisheng_seeker`；广角/长焦共用 `rtsp://主机:8554/aisheng_seeker`，切换镜头时 URL 不变，网关停止旧编码并启动新镜头编码。
- 接收端：`rtspsrc protocols=udp latency=0` → `rtph264depay` → `h264parse` → `nvh264dec` → `videoscale`（显示 960×540）→ `videoconvert n-threads=4` → BGR `appsink`。
- 演示默认相机和编码均为 1920×1080@30；当前 WSL/RTX 4060 环境单路 1080p 实测编码/解码 29～30fps。
- 产品文档写 UDP H.264/H.265 裸流；仿真使用 RTSP over RTP/UDP，未实现视频 SEI。两者差异在对接真实数据链时需要适配。
- 当前不实现视频 SEI、OSD 烧录和多客户端视频订阅管理；数字变焦由上位机显示端按遥测状态做中心裁剪，RTSP 流保持全视场。

## 限制

- 标准遥测的角速度/失调角字段按协议 ±20°/s 限幅；实际 60°/s 框架转速在 Gazebo 插件 JSON 中保留。规格书的视线角速度范围是 ±25°/s，与协议字段 ±20°/s 不同；当前标准帧按 ±20 发送，插件内部 `target_los` 保留实际值。25°/s 跟踪验收已通过：内部峰值 26.21°/s、标准帧 20.00°/s、稳态 TRACK 100/100、最大失调角 0.18°。
- 演示目标飞机当前为静态；移动目标航线和自动重捕的完整动态验收尚未完成。
- 标准协议没有广角/长焦切换命令；`0x53` 是仿真映射。
- 单客户端控制设计；多客户端控制权仲裁、认证和加密不在当前范围。
