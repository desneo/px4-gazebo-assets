# 中科 DYT 二进制与 JSON

标准格式依据本目录《中科友成-DYT控制协议.docx》。中科组件用同一 UDP socket 发送 16 字节控制、接收从网关同一配置端点回传的 32 字节遥测。所有多字节整数使用 little-endian；帧长度、头、校验和及参数不合法时拒绝处理。标准数据报不携带 JSON 封套、设备 ID、seq 或 ACK。

## 控制帧

| Byte | 类型 | 内容 |
| --- | --- | --- |
| 0～1 | U8×2 | `EB 90` |
| 2 | U8 | 控制信息 cmd |
| 3～4 | LE S16 | X |
| 5～6 | LE S16 | Y |
| 7 | U8 | 参数 3，当前支持指令填 0 |
| 8 | S8 | 变焦速率，当前支持指令填 0 |
| 9～14 | 6 bytes | 预留，填 0 |
| 15 | U8 | `sum(byte0..14) & 0xFF` |

| Cmd（十六进制） | 功能 | X/Y 与行为 |
| --- | --- | --- |
| `00` | 空指令 | 参数为 0，只建立/维持租约，不启动运动 |
| `24` | 手动速度 | raw×0.1°/s，方位右正、俯仰上正；退出自动和旧跟踪 |
| `26` | 指定框架角 | raw×0.01°，统一使用实际限速与行程；超行程明确拒绝 |
| `2B` | 归中 | 参数为 0，回机械 0/0，非位置瞬移 |
| `0D` | 指点跟踪 | 原图中心原点整数 px，X 右正、Y 下正 |
| `0E` | 停止跟踪 | 参数为 0，退出跟踪及自动重选 |
| `0F` | 自动锁定 | 参数为 0，无候选等待，中心最近者优先 |

指点像素的 Y 向下是本仿真对厂商未明确方向部分的约定；GUI 按显示缩放还原原图后，发送 `X=u−width/2`、`Y=v−height/2`。整数参数采用最近整数、半单位远离零；编码溢出直接报错，不静默 wrap。单轴回零使用 `26`，另一轴取新鲜实测角；缺少有效姿态时禁用。

完全停止由 GUI 发送 `0E` 与 `24(0,0)`；人工释放立即发送 `24(0,0)`。未实现的红外、在线变焦、激光及其他控制指令不执行，不用另一动作代替，不编造厂商错误 ACK。

## UDP 对端与控制时效

默认监听 `127.0.0.1:8870`。首个完整合法且受支持的控制帧建立单客户端租约，默认 2 s；租约内其他端点不接管。GUI 空闲每 0.2 s 发 `00`，人工按住时每 0.1 s 发 `24`。坏包、未知指令和非当前对端的数据既不改变回传地址，也不刷新租约。

当前非零 MANUAL 速度默认超过 0.5 s 未刷新即停车，`00` 不刷新该计时。接受跟踪、自动锁定、回零、指定角或停止时撤销旧人工计时，避免旧 MANUAL 超时抢停新模式；对端租约仍独立生效。租约到期停止全部控制、退出自动并停止向旧端点回传。

`0D` 不自动重传；无 seq 的重复指点可能重新选择。自动开启、归中和停止按幂等语义处理。GUI 只显示“已发送”，不因 socket 成功宣称已经执行；执行状态由新鲜遥测和本机诊断显示。

命令行工具按实际会话端点发送标准帧，例如：

```bash
../.venv-zhongke-d80/bin/python tools/send_command.py manual --session demo --x 10 --y -5 --duration 1 --quiet
../.venv-zhongke-d80/bin/python tools/send_command.py home --session demo --duration 3 --quiet
```

这些工具与 GUI 使用相同单客户端租约，运行前应关闭另一个控制客户端。

## 二进制遥测

| Byte | 字段 | 转换 |
| --- | --- | --- |
| 0～1 | 帧头 | `EE 16` |
| 2 | status1 | 完整原始字节 |
| 3 | status2 | 完整原始字节 |
| 4、5 低 4 位 | zoom | `(b4 + ((b5 & 0x0F)<<8))×0.1` |
| 5 | status3 | 完整原始字节，低 4 位也承载 zoom 高位 |
| 6～7 | offset_x | LE S16×0.05° |
| 8～9 | offset_y | LE S16×0.05° |
| 10～11 | frame_roll | LE S16×0.01° |
| 12～13 | frame_pitch | LE S16×0.01° |
| 14～15 | frame_yaw | LE S16×0.01° |
| 16～19 | 预留 | 编码为 0，不加入 JSON |
| 20～21 | roll_rate | LE S16×0.01°/s |
| 22～23 | pitch_rate | LE S16×0.01°/s |
| 24～25 | yaw_rate | LE S16×0.01°/s |
| 26～27 | laser_range | LE U16×0.1 m，0 无效 |
| 28 | self_check | 完整原始字节 |
| 29～30 | 预留 | 编码为 0，不加入 JSON |
| 31 | 校验和 | `sum(byte0..30) & 0xFF` |

框架角和角速度取真实机械关节测量，不使用命令值、世界 Euler 角或目标惯性视线速度。没有横滚关节，`frame_roll/roll_rate=0`；没有激光测距，`laser_range=0`，不能用真值距离冒充测距。

目标偏差约定水平右正、垂直上正，使用当前 `fx/fy`。只有已绑定且观测有效才置 `status1.bit2`，无效时清除该位并令偏差为 0。`status1.bit3` 不表示自动锁定开关；未实现独立目标自动提示时保持 0。`status2.bit3` 表示实际控制/电机使能，停止运动不等于断电。未实现的激光、存储、图像增强、电锁、载机跟随等状态位不伪装启用。

`self_check.bit7` 在控制、关节和成像初始化完成后置 1；真实关节/控制故障对应 bit1、成像故障对应 bit0。没有陀螺校准模型，bit2 为 0。协议字段量化不承担伺服限速；若实际测量超出 20°/s，外发必须如实反映可表达的测量，而不是转换层限幅掩盖。

## JSON 外发

数据链为：新物理测量 → 网关编码 → 实际 UDP → GUI 校验解码 → 发送队列 → JSON。地面站严格检查配置来源 IP/端口、恰好 32 字节、帧头及校验；诊断和内部 JSON 不能替代该二进制来源。

每个 UTF-8 JSON 数据报恰好包含以下 15 字段，名称对应指定 `DytZhongkeTelemetry.msg`：

| 字段 | 类型与单位 |
| --- | --- |
| timestamp | 非负整数，实际发送前生成的 Unix 毫秒，不来自原始帧 |
| status1、status2、status3 | 0～255 整数，原始字节 |
| zoom | 有限数值，无量纲倍数，默认 1.0 |
| offset_x、offset_y | 有限数值，° |
| frame_roll、frame_pitch、frame_yaw | 有限数值，° |
| roll_rate、pitch_rate、yaw_rate | 有限数值，°/s |
| laser_range | 有限数值，m，0 表示无效 |
| self_check | 0～255 整数，原始字节 |

不包含 `type`、设备 ID、目标名称、内部接收序号或其他艾晟字段。数值不允许 bool、NaN 或 Infinity，不重复缩放已经还原的物理量。JSON 时间戳采用发送端 Unix 毫秒，不修改 PX4 的本地发布时钟。

每份合法 UDP 数据报获得本地接收序号和单调接收时间；内容相同的不同数据报仍是不同采样，不按内容 hash 去重。同一接收序号至多发送一次。独立线程使用长度 16 的队列，过载丢旧并统计，超过默认 1 s 的条目不发送。启动、停止、编辑地址和关闭都会清队列并切换发送会话；停发期间的数据不会在下一次启用时回放。

源暂停或失效不靠重复缓存维持 60 Hz。接收和发送频率按最近 2 s 的真实单调时钟窗口统计，最初 0.25 s 为预热，停发后发送 Hz 立即为 0。发送成功仅表示交给本机 socket，接收效果由实际目的端验证。

## 真值与诊断边界

候选来自配置中精确名称的实体原点投影，不进行图像检测或实体遮挡判断。初次发现/重新选取要求有效新鲜数据、相机前方、中心在画面内、相机到目标三维距离不超过默认 300 m。等距候选按实体名称稳定排序。双击按离点击最近选择，自动按离画面中心最近选择；正常 TRACK 不换目标。

发现距离不限制已锁目标持续跟踪。失效时停止旧输出并清有效偏差，自动按配置周期尝试重新选择，人工指点不会自动改锁其他实体。重新选取再次执行距离条件。标准指点帧没有 frame_seq，处理时采用网关最近新鲜候选；不承诺与客户端显示帧精确配对。

本机 `/zhongke_d80/diagnostics` 使用同一会话的 Gazebo Transport 分区，提供配置 hash、模型名、目标身份、模式、WAIT/TRACK/TEMP_LOST/LOST、原因、限位、退化、命令处理结果及实际内参。GUI 按模型名和配置 hash 校验且检查新鲜性；诊断失效时身份和原因显示未知。该话题只读，不属于标准 UDP，不加入 15 字段 JSON，也不产生外部控制通道。
