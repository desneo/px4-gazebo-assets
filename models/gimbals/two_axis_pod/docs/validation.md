# 两轴吊舱验证

## 验证环境与范围

使用 Gazebo Harmonic（Sim 8、Transport 13、Msgs 10）、OpenCV C++/Python、GStreamer NVIDIA NVENC/NVDEC。演示世界使用独立 Gazebo 分区，Ø84 mm 底部圆环水平固定在台面，导引头整体向上高 91 mm。Python 网关和 Linux 地面站共用仓库根目录的可重建 `.venv-linux`，其中包含 OpenCV Python，并复用系统 Gazebo/GStreamer 绑定。两个启动入口均在环境缺失时自动配置，虚拟环境不入库。

## 已通过检查

- 基本模型与演示世界通过 `gz sdf -k`。
- 四项模型测试验证工程尺寸、底环水平方向、91 mm 竖直外廓、罩壳归属偏航 link、实际 SDF 关节链、光学姿态、机械角边界及生成一致性。
- CTest 验证 `Rz(yaw) Ry(pitch)` 运动学、图像 Jacobian、朝天退化、速度/加速度与前瞻限位、机械回零、故障锁定、CSRT 跟踪及断帧停止/丢失。
- 95 项地面站/网关测试覆盖 Station INI 配置与 JSON 拒绝、协议 v4、两轴控制、拒绝滚转、seq 去重/乱序/回执、四个互斥视觉模式、自动检测到 CSRT 单目标交接、网关层人工转动抢占、手动框选保护、视觉遥测校验、Linux 强制 NVDEC、Windows D3D11 硬解参数与软件回退拒绝、摇杆续发、释放和焦点保护。
- 16 项视觉核心/网关环境测试覆盖单类 YOLO11 输出解析、NMS、连续命中确认、误检过滤、ByteTrack 高低置信两阶段关联、Kalman 预测、Hungarian 全局匹配、稳定 ID、中心最近选择、RGB 红框、模型路径校验和 OpenCV DNN 实际加载归档 ONNX。
- Gazebo 在线检查验证默认零位朝天、两路真实渲染、实际 CSRT TRACK 状态、四端限位及稳定回零、单轴复位保持另一轴、手动停止续发后停车，以及朝天退化处偏航仍可机械运动。
- 地理场景的地面站 UDP 在线自检收到 201 条遥测（约 50.1 Hz），协议 v4 和 home 回执有效；机械姿态回到 yaw `0°`、pitch `−0.024°`，两轴速度为零。
- 完整地理场景识别到 3 个飞机目标；1920×1080@30 Hz 输入 30.35 fps、视觉输出 30.20 fps、模型推理约 14.9 ms。自动锁定选择一个已确认轨迹并进入 CSRT TRACK，连续 2 秒未切换目标。
- RTSP 使用 NVENC，地面站使用 `nvh264dec`；5 秒检查取到 104 帧，帧序号识别成功率 100%，有效取帧阶段约 30.6 fps，实际解码帧含三个红框和 `#1/#2/#3` 轨迹号。
- Gazebo 外形与底环水平立装方式、地面站视频及两轴控制已通过人工确认。

## 额外 UDP 状态输出

隔离部件场景使用独立分区 `two_axis_status_udp_validation`。额外状态目标为本机 `127.0.0.1:18800`、配置 20 Hz；原 station 控制端口为 `18766`、遥测配置 50 Hz。约 5.008 秒采样中，额外接收端收到 100 包（19.97 Hz），station 收到 249 包遥测（49.72 Hz）。额外接收端在 station 登记前已收到状态，station 的 v4 hello、ping/pong 和 home 执行回执均正常。

额外数据报保留原 station 的全部遥测字段，最大采样报文 2508 字节，低于 8 KiB 上限。实际插件停止后，最后一包在约 0.97 秒后到达，之后额外发送按 1 秒时效暂停。新增发送使用独立 socket 与线程；关闭额外输出后 station 仍可通信。配置默认关闭；默认频率、地址校验、非法配置拒绝、超长或非法 JSON 丢弃、发送异常恢复及遥测过期恢复由标准库测试覆盖。

实际网关采样记录为 `runs/two_axis_status_udp_validation/status_udp.validation.json`，日志与运行世界均不入库。

## 限制

外廓尺寸依据设计资料生成，复杂曲面、支架、球心位置、孔位分布、碰撞体、质量和惯量仍为仿真近似，未做实物质量标定。固定安装演示不验证载机动态补偿、PX4 联动或实物控制。两轴结构不提供独立滚转稳定；pitch 接近 0°、镜头朝天时，偏航轴无法调整视线方向。在线检测使用仿真固定翼外形，未覆盖所有真实飞机外观、高速目标、长时间遮挡或所有光照条件。Linux 硬件视频结果适用于本机 RTX 4060、当前驱动和 GStreamer NVIDIA 插件；缺少 NVENC/NVDEC 时组件明确失败，不提供软件回退。Windows 入口强制请求并校验 D3D11 硬件解码，代码级回退拒绝已覆盖测试，实际显卡驱动和 OpenCV wheel 兼容性需在目标 Windows 机器执行 `--decode-test` 验证。

## NVENC 与 NVDEC

生产编码管线使用 `nvcudah264enc` 的低延迟 CBR 配置，实际输出 8 位 `yuv420p` H.264。独立兼容性测试在临时 RTSP 端口连续取流并确认至少 40 帧；共享 RTSP 四项测试使用生产 NVENC 和 `nvh264dec`，验证双路颜色隔离、重复路径拒绝、单路退出、租约过期和中继重启恢复，均通过。

宿主 GPU 为 RTX 4060，驱动 595.99.02。近生产链路 `BGR 1920×1080@30 → videoconvert → NVENC → h264parse → NVDEC → BGR` 连续处理 180 帧用时 6.012 秒，无错误。默认沙箱不暴露 `/dev/nvidia*`，硬件测试必须在宿主环境运行；沙箱内的设备缺失不能判定显卡故障。
